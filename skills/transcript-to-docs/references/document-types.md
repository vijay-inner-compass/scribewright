# Choosing the document

Pick by what the transcript is, not by what the user typed. If it is mixed (for example a class that ends with action items), build the main type and add a final page of the second type.

## 1. Training / class session → setup guide, study note or cheat sheet

Page patterns (use what the content supports):
1. **Concept page**: flow strip of the mental model, "which route do I take" decision table, facts panel, procedure cards (one per platform/route).
2. **Do and verify page**: proof-it-works code block, command/shortcut reference table, build-a-thing steps.
3. **Recover page**: "where it actually breaks" list, six-values tiles, debug-order mnemonic if taught, go-deeper links, glossary.

Capture: the learning outcome, prerequisites, exact commands and settings, versions, common learner errors and what the instructor said about each, exercises and homework with deadlines, tools and links mentioned.

## 2. Business meeting / call → meeting record

Pages:
1. **Summary page**: tagline = the outcome in one sentence; decisions table (Decision | Rationale | Owner | Source timestamp); facts panel with figures, dates, budgets; a short "context" card.
2. **Actions and risks page**: action table (Action | Owner | Due | Status), risks/blockers list in the breakage style, open questions card, next meeting.

Capture: attendees (only if stated), decisions with who made them, actions with owner and date, figures, risks, dependencies, what was deferred. If an owner or date was not stated write "Not stated"; do not guess. Keep it to one page if the meeting was short.

## 3. Client / consulting workshop → engagement brief

Pages:
1. **Situation and requirements**: flow strip of the current vs target process, requirements table (Requirement | Priority | Source), constraints in the facts panel.
2. **Options and trade-offs**: comparison table (Option | Strengths | Risks | Cost or effort), recommendation card (accent), assumptions.
3. **Plan and risks**: phased steps, owners, risks and mitigations, open questions, glossary.

Capture: problem statement, stakeholders, success measures, constraints, options considered, the chosen direction and why, cost/effort figures, assumptions. Mark inferred items "to confirm".

## Any other transcript

Choose the closest type above, or use the generic pattern: concept page, procedure/reference page, risks page. Say in one line which you chose.

## Length

Match the transcript, not a fixed count. A 20 minute call is one page; a two-hour technical session is three to five. If a single topic runs past five pages, propose splitting it into separate documents.

## Research pages (added to every type)

After the session pages, add the pages from `references/research-guide.md`, scaled to the type:

- **Training / class session**: Foundations, one or two Go deeper pages of concept explainers, Practice path, Sources. This is the main learning resource for freshers.
- **Business meeting**: a light pass only: verify figures and dates, define unfamiliar terms in the glossary, and add a short Sources list if anything external was checked. No practice path.
- **Client workshop**: verify claims and standards, add background on the options compared (with sources), and a "read before the next meeting" list.
